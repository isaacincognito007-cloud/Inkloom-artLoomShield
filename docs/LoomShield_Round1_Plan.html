1. My Understanding of the Given Problem Statement

01 / PROBLEM

Growing organisations publish content simultaneously through internal employees, regional teams, external agencies, and AI drafting tools. Just as a general image model produces something that merely looks logo-shaped without respecting typographic weight, clear-space ratios, or lockup geometry, unguided content creation produces material that looks finished but quietly breaks brand identity and factual accuracy across six areas:

1. Unsupported Claims
Unverified superlatives ("#1 fastest", "100% guaranteed ROI") and outdated product numbers get published without factual backing, creating legal and reputational risk.
2. Tone & Voice Drift
External agencies and AI drafting tools often adopt alarmist, overly casual, or off-brand tone that conflicts with the organisation's character.
3. Terminology Errors
Deprecated product names, prohibited buzzwords, and inconsistent capitalization weaken brand consistency across channels.
4. Off-Brand Visuals & Lockups
Visuals use unauthorized hex colors (high CIE ΔE deviation), broken typography scales, or violated logo clear-space and lockup rules.
5. Accessibility Gaps
Low text contrast (<4.5:1), missing image alt-text, overly complex prose, and skipped heading levels violate WCAG 2.1 AA standards.
6. Unclear Guidelines
Existing checkers either reject drafts without citing the rule, overwrite the writer's voice, or fail to show leadership which brand guidelines are unclear.
Which Specific Part of the Problem I Intend to Solve

Static PDF style guides are ignored under tight deadlines, while generic cloud AI wrappers incur ongoing API costs, risk leaking confidential pre-launch materials to third-party servers, and rewrite copy without citing rules. I am designing LoomShield to solve pre-publication brand governance as a constraint-driven system: checking multi-format content locally against approved guidelines, facts, and visual specs, explaining each issue with an exact source citation, suggesting surgical fixes that preserve the creator's purpose, supporting role-based approval workflows, and highlighting where the brand guidelines themselves are ambiguous.

3. My Proposed Solution: LoomShield

03 / SOLUTION

My proposed solution is LoomShield—an intelligent, local-first brand-governance platform launched via the Shield Your Loom → LoomShield action menu. Rather than asking one general cloud prompt to critique a draft, LoomShield evaluates text, documents, and visual assets against concrete constraints stored in the organisation's Brand Vault (tone rules, terminology lexicon, verified fact sheet, typography/symbol clear-space rules, and approved hex palette). For every issue found, it explains why it was flagged, cites the exact rule or fact source, proposes a surgical correction, and routes the draft through a role-based review workflow.

Local-First, Cloud-Optional Architecture (100% Zero-Key Dual On-Device Engine)

LoomShield does not require users to pay for external AI API services, reducing operational costs to $0 while giving organisations full privacy and control over confidential materials. My design follows four strict rules:

  1. Process ordinary requests with deterministic rules and embedded NLP: All everyday inspections across tone, terminology, messaging, promotional claims, visual/lockup consistency, and accessibility run locally on-device using deterministic rules paired with embedded machine-learning NLP (TF-IDF vectorization, cosine similarity fact retrieval, tone polarity scoring, Flesch-Kincaid readability, CIE ΔE color distance, clear-space boundary checks, and WCAG 2.1 contrast math).
  2. Use a cloud AI API only for requests that genuinely need advanced language reasoning: An optional cloud escalation gate is used only when a user explicitly requests complex multi-paragraph rhetorical restructuring and confidential mode is disabled.
  3. If no API key is configured, keep all local features working and explain which advanced features are unavailable: With zero API keys configured, 100% of the core 6-pillar inspections, surgical suggestions, visual heatmaps, and ambiguity insights work locally, while the UI clearly states which optional cloud feature is inactive.
  4. Keep any cloud API key on a secure backend, not in public frontend code: Any optional API key is stored strictly in backend environment variables (.env) and never exposed in client-side code.

Most Technically Challenging Part & How My Planned Architecture Solves It

Technical Challenge: Detecting unsupported promotional claims (for example, "cuts settlement time by 95%") and suggesting corrections that preserve the writer's voice without hallucinating facts or relying on paid external LLM APIs.
My Planned Solution: I combine Tier 1 (Deterministic Regex Span Extraction) with Tier 2 (Embedded TF-IDF Cosine Similarity RAG). Tier 1 locates statistical claims and superlatives with exact character offsets [start, end]. Tier 2 vectorizes the claim context and measures cosine similarity against the Verified Fact Sheet. When a draft exaggerates a number (such as claiming "95% faster" when FACT-101 verifies "up to 64% faster"), LoomShield cites FACT-101 and swaps only the inaccurate clause while keeping the rest of the creator's sentence untouched.
