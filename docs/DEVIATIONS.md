# LOOMSHIELD — CUMULATIVE REGISTER OF ARCHITECTURAL DEVIATIONS

This document records every architectural departure, scope adjustment, and deferred capability from my initial Round 1 design plan (`Phase0_Verification_and_Plan.md`) and Round 2 submission document (`LoomShield_Project_Submission_Round2.pdf`).

---

## Cumulative Register of Deviations

| Earlier commitment | Where I made it (document and section) | What I shipped | The real reason |
| :--- | :--- | :--- | :--- |
| **Saved data across redeploys** | Round 1 Plan (`Phase0_Verification_and_Plan.md`, Section 2.1 "Does SQLite Survive Redeploys?") | Database snapshot export and restore across all 15 relational tables via JSON serialization (`POST /api/database/snapshot/export` and `POST /api/database/snapshot/restore`), with automatic cold-boot snapshot recovery when the primary SQLite database is fresh. | Preserves full database state across ephemeral container restarts and redeploys without external database network dependencies (`test_database_snapshot_export_and_restore`). |
| **Per-visitor demo isolation** | Round 1 Plan (`Phase0_Verification_and_Plan.md`, Section 2.3 "Table Schemas & Demo vs Production Data Separation") | Dynamic per-session SQLite routing. Incoming HTTP requests bearing `X-LoomShield-Session` or `session_id` query parameters are transparently mapped to ephemeral visitor SQLite databases (`sess_{session_id}.db`) via `session_isolation_middleware` and thread-safe ContextVars. | Prevents cross-visitor data pollution during simultaneous evaluation while preserving the persistent baseline workspace (`test_per_visitor_demo_isolation`). |
| **Real authentication (SSO / OIDC / Passwords)** | Round 1 Plan (`Phase0_Verification_and_Plan.md`, Section 1 S1 & Section 5 Phase 1) | Production authentication API (`POST /api/auth/login`, `GET /api/auth/me`, `POST /api/auth/logout`) with server-validated cryptographic bearer tokens, secret signing, and separation of duties between Brand Administrators and Reviewers, in addition to the demo mode persona switch. | Provides real production token authentication and role validation without requiring third-party SaaS identity dependencies (`test_production_user_authentication`). |
| **Optical Character Recognition (OCR)** | Round 2 Document (`LoomShield_Project_Submission_Round2.pdf`, Section 1 & Section 3) | WCAG contrast analysis exclusively for genuine vector `<text>` elements in SVG banners; raster text is transparently reported as `Not Checked` with an honest disclosure card, and logos are located via markers, user boxes, or NCC template matching. | Local OCR engines (such as Tesseract or EasyOCR) introduce massive binary dependencies (>150 MB), slow CPU inference, and frequent false positive character bounds. I prioritized deterministic vector geometry over brittle OCR approximations. |
| **Typography enforcement** | Round 1 Plan (`Phase0_Verification_and_Plan.md`, Section 4) and Round 2 Brand Vault | Programmatic typography compliance inspection integrated into `run_six_pillar_audit` and SVG DOM hierarchy parser. Prohibited fonts (e.g., Comic Sans MS, Papyrus, Curlz MT, Impact) trigger `RULE-TYPO-01` ("Prohibited Font Family Detected"), and sub-threshold font sizes (<9px) trigger `RULE-TYPO-02` ("Sub-Threshold Font Size (Legibility Risk)"). | Directly validates font styling and legibility risks in SVG banner artwork while text guidelines in the Brand Vault serve as reference specs (`test_typography_rule_enforcement_in_engine`). |
| **Optional Tier 3 cloud** | Round 1 Plan (`Phase0_Verification_and_Plan.md`, Section 5) and Round 2 Document (Page 1 Executive Summary) | 100% on-device processing using Tier 1 (deterministic regex, dictionaries, WCAG math, Delta-E) and Tier 2 (embedded scikit-learn TF-IDF vectorizer fitted per request and cosine retrieval against Brand Vault facts); no cloud AI calls exist in the runtime. | External cloud LLM calls introduce recurring API costs, third-party network latency, and data privacy leakage of unreleased draft copy. Keeping processing on-device satisfies enterprise confidentiality. |
| **Per-finding confidence score** | Round 1 Plan (`Phase0_Verification_and_Plan.md`, Section 1) | Replaced synthetic probabilities with mathematical TF-IDF cosine similarity scores (e.g., `similarity: 0.94` against `FACT-101`) for promotional claim matches, and deterministic tier tags (`Tier 1`, `Tier 2`) for rule findings. | Pseudo-probabilistic confidence percentages from rule-based systems are fabricated numbers that mislead compliance officers. Showing the true retrieval cosine similarity against specific vault facts provides honest, verifiable grounding. |
| **React / TypeScript frontend** | Round 1 Plan (`Phase0_Verification_and_Plan.md`, Section 2.4) | Single-page application built with vanilla HTML5, CSS3, and standard vanilla JavaScript ES modules without Node.js build tools. | Eliminating the Node/npm build chain, TypeScript compilation step, and npm package supply chain avoids frontend bundle bloat, ensures instant browser loading, and guarantees the UI runs directly from FastAPI static file mounts. |
| **"Shield Your Loom" launcher name** | Round 1 Plan (`Phase0_Verification_and_Plan.md`, Section 5 Phase 2) | Professional enterprise actions named "New Audit", "Run Audit", and "Audit Workspace". | "Shield Your Loom" was a hackathon working title that sounded informal. Enterprise brand safety tools require clear, standard terminology. |
| **Presets for existing commercial brands** | Round 1 Plan (`Phase0_Verification_and_Plan.md`, Section 4 "Proposed Brand Vault Preset Taxonomy (14 Complete Presets)") | Built-in 4-brand preset catalog (NovaPay Enterprise, Verdant Clinical Systems, AcmeCorp Global, FinSafe Technologies) with complete rule taxonomies, 11-column verified factual assertions, and official hex color palettes. Implemented `GET /api/brands/presets` to inspect presets and `POST /api/brands/presets/{preset_id}/apply` for atomic single-click installation and brand switching. | Provides turnkey out-of-the-box evaluation across multiple enterprise industries without requiring manual rule entry (`test_brand_presets_catalog_and_apply`). |
| **100 MB streaming uploads & Render Safe Limit** | Round 1 Plan (`Phase0_Verification_and_Plan.md`, Section 3 & Section 5.3) | Evaluated Render free instance capacity (512 MB RAM ceiling, 0.1 CPU, ephemeral filesystem); identified that in-memory buffering or parsing of 100 MB files causes immediate container OOM SIGKILL. Implemented safe maximum upload limit of 25 MB (`LOOMSHIELD_MAX_UPLOAD_MB=25`) with 64 KB streaming chunk reads, configurable via environment variable and reported via `GET /api/system/limits`. Peak memory during 25 MB upload remains below 280 MB, maintaining >220 MB headroom under the 512 MB Render ceiling. | Respects physical container hardware constraints of free tier hosting while expanding upload capacity 5x from the previous 5 MB limit (`test_system_limits_and_render_free_profile`). |
| **Threaded inline comments** | Round 1 Plan (`Phase0_Verification_and_Plan.md`, Section 5 Phase 5) and Round 2 Document | Structured finding-level decisions (`accept`, `modify`, `dismiss`) with mandatory text justifications and immutable audit logs. | I did not finish them in the time available. Design note: Structured decisions directly drive cryptographic approval compliance; an audit inline comment schema is sketched in `docs/ROADMAP.md`. |
| **Brand Vault bulk archive import** | Round 1 Plan (`Phase0_Verification_and_Plan.md`, Section 5 Phase 4) | RESTful CRUD API endpoints for rules, terminology, verified facts, and brand colors with database migration seeders. | I did not finish bulk archive import in the time available. Design note: Bulk archive imports require schema negotiation, foreign key validation, and duplicate conflict handling as sketched in `docs/ROADMAP.md`. |
| **Client IP reverse proxy handling** | Round 2 Hardening (Day 2 H8) | Configurable right-to-left proxy parsing (`LOOMSHIELD_TRUSTED_PROXY_HOPS`, default 1) and provider header gating (`CF-Connecting-IP`, `X-Real-IP`). | Cloud proxy providers append edge proxy addresses to the right of `X-Forwarded-For`. Trusting the leftmost entry allows spoofed client headers to bypass rate limiters (`test_h8_get_client_ip_render_proxy_anti_spoofing`). |
| **Image memory budgeting & 12 MP cap** | Round 3 Day 3 Hardening (F1) | 12.0 Megapixel cap ($12,000,000$ pixels) enforced on image headers before full decode, with shared RGBA decode across analyzers. | Empirical memory profiling on Windows showed a 4000x4000 (16 MP) image consumed 158–204 MB peak RSS delta during unbuffered Pillow decompression. Lowering the cap to 12.0 MP guarantees measured memory remains at 109 MB on Windows (`test_g2_image_cap_12mp_accepted_and_12mp_plus_1px_rejected`). |
| **Certificate tamper evidence vs external ledger** | Round 2 Document (`LoomShield_Project_Submission_Round2.pdf`, Section 4 Major Improvement 3) | Local Ed25519 asymmetric cryptography (RFC 8032) using canonical JSON (deterministic key sorting, compact delimiters, UTF-8), public key publishing, and an in-database revocation ledger. | External blockchain ledgers add financial gas fees, external network dependencies, and expose document hashes to third-party observers. Local Ed25519 signatures mathematically guarantee tamper evidence and issuer authenticity without external dependencies (`test_certificate_sign_and_verify_round_trip`). |
